# Plata design system (Compose Multiplatform)

Android + iOS, one module `:shared`, all UI in `shared/src/commonMain/kotlin/tech/bashga/plata/`. The brief is `../ds/COMPOSE.md`; tokens come from `../ds/foundations.md`, components from `../ds/inventory.md`.

## Commands

Run from `cmp-app/`. Gradle may be busy with another agent: on a lock timeout wait and retry. Never `clean` or delete `build/`.

| what | command |
|---|---|
| build both platforms | `./gradlew :shared:compileKotlinIosSimulatorArm64 :androidApp:assembleDebug` |
| render every screenshot | `./gradlew :shared:recordRoborazziAndroidHostTest` |
| render one test class | `./gradlew :shared:testAndroidHostTest --tests '*ListRowScreenshots'` |
| render one test | `./gradlew :shared:testAndroidHostTest --tests '*FoundationsScreenshots.icons'` |
| link the iOS framework | `./gradlew :shared:linkDebugFrameworkIosSimulatorArm64` |
| compare a screen | `tools/compare.sh <screen-id>` → `screenshots/compare/<screen-id>.png` |
| zoom into a region (points, fractions allowed) | `tools/compare.sh <screen-id> <x> <y> <w> <h>` → `screenshots/compare/<screen-id>@x,y,w,h.png` |
| compare a component variant | `tools/compare-component.sh <component>/<variant>` → `screenshots/compare/component/<component>/<variant>.png` |
| compare against another reference | `tools/compare-component.sh <component>/<variant> <reference.png>`, e.g. a crop made with `../.claude/skills/ds-teardown/crop.sh <screen-id> x y w h /tmp/ref.png` |
| regenerate Figma glyphs | `python3 -I tools/figma_glyphs_to_kotlin.py tools/figma/glyphs-73-2.svg tools/figma/glyphs-73-2.positions > shared/src/commonMain/kotlin/tech/bashga/plata/designsystem/icons/PlataIcons.kt` |

`recordRoborazziAndroidHostTest` and `testAndroidHostTest` do the same thing here: the harness always records (it passes `RoborazziTaskType.Record`), and the test task never counts as up to date, so every run rewrites its PNGs. Roborazzi's compare/verify tasks are not used; `compare.sh` is the check.

Compare images are three panels: reference | render | 50% overlay, with magenta gutters (and magenta padding where a component render and its specimen differ in size; both are top-left aligned). Screen renders are 1179×2556 (393×852pt @3x), the source minus its watermark bar. Look at them with the Read tool.

## Foundation helpers

- **Text**: `PlataText(text, style, color)` wraps `BasicText`. `GradientText(text, style, brush)` hugs its text and spreads the gradient across it (all lines). A `SpanStyle(brush = …)` inside an `AnnotatedString` is sized to the whole paragraph, not the span, so one gradient word in a sentence only shows a slice of the gradient; set such a word as its own `GradientText` in a `Row`/`FlowRow`, or build a brush with explicit start/end offsets. `PlataText(AnnotatedString)` folds a `\n` into any size/weight/letter-spacing span that ends or starts at it (step 4): on Android a newline left alone in its own run carries taller fallback metrics into the line-height span, which then grows the first and last line of the paragraph by 1.33 and 1.67 (36 → 39.33 for two lines). Colour-only spans, soft wraps and spans followed by text on the same line were never affected.
- **Line boxes**: `display` is 30/36 since step 3 (the sources space PromoHeadline lines 36 apart; at Figma's 34 the Android host grew each line to the font's own 35.3). Every style is exact on the host now.
- **Line boxes**: every style uses `LineHeightStyle(Alignment.Center, Trim.None)`, so a text box is exactly `lineHeight × lines`, the same box Figma and the inventory measure. (The brief suggested trimming; trimming would make single-line boxes shorter than their Figma counterparts by the half-leading, so measured paddings would come out short.)
- **Press feedback**: `PlataTheme` installs `PlataPressIndication` as `LocalIndication`: the pressed element fades to 60% opacity, no ripple. Use `Modifier.pressable { … }` for tap targets.
- **Shapes**: `ContinuousRoundedShape(radius)` is Figma's corner-smoothing squircle at 0.6 (iOS continuous corners); pass `smoothing = 0f` for a circular corner. Radii ≥ half the short side become capsules, so `ContinuousRoundedShape(radii.full)` is a pill. `ContinuousTopRoundedShape(radius)` rounds only the top (sheets). The Figma components use smoothing 0; use the continuous shape where the source shows the iOS curve (sheets, dialogs, cards, buttons) and check against the compare image.
- **Safe area**: screens read `PlataSafeArea.current.top/.bottom` and never draw the status bar or home indicator. `App()` provides the window insets (`ProvideWindowSafeArea`); `screen()` in the harness provides `PlataSafeArea.IPhone` (59/34).
- **Navigation**: see `ARCHITECTURE.md`. Stateful screens take navigation lambdas; the old per-screenshot screens still call `LocalFlowNavigator` (a no-op now).

## Adding a component

1. Read its inventory entry, specimens (`ds/specimens/<component>/`) and a source screen.
2. Create `designsystem/components/<InventoryName>.kt`. Variants become enums or typed parameters, props become parameters, slots become `@Composable` lambdas. Foundation primitives only, no Material.
3. End the file with `@Preview` functions covering its variants. Make them `internal` (not `private`) so the screenshot tests can call them.
4. Add `shared/src/androidHostTest/kotlin/tech/bashga/plata/screenshots/<InventoryName>Screenshots.kt`:

   ```kotlin
   class ListRowScreenshots : ScreenshotTest() {
       @Test fun singleDefault() = component("list-row/size=single,state=default,surface=plain") { ListRowSinglePreview() }
   }
   ```

   The name is the specimen's path under `ds/specimens/` without `.png`. `component(name, background = { it.surfaceBackground }, margin = 4.dp)` renders at the component's own size, inset by the ~4pt margin the specimens have; pass `background = { it.surfaceCard }` for specimens cropped from white cards.
5. `./gradlew :shared:testAndroidHostTest --tests '*ListRowScreenshots'`, then `tools/compare-component.sh list-row/size=single,state=default,surface=plain` and read the compare image.

When the specimen crop isn't the component's bounds plus a uniform margin (hit areas larger than the label, overhanging badges, shadows, off-centre crops), frame it like the crop: `component(name, margin = 0.dp) { SpecimenFrame(cropW, cropH, x, y) { Preview() } }` places the component's top-left at (x, y) in a cropW×cropH window (`screenshots/SpecimenFrame.kt`). Specimens cropped over photos use a sampled backdrop colour as the test background (test code may use literal colours).

Content taller than 852pt is cut at the window edge; give such a test class its own `@Config(sdk = [36], qualifiers = "w393dp-h2000dp-xxhdpi")` (see `FoundationsScreenshots`). One test class per component or screen area, one file each, so agents working in parallel never edit the same test file. `ScreenshotTest` carries the Robolectric setup (`@Config(sdk = [36], qualifiers = "w393dp-h852dp-xxhdpi")`, native graphics).

- **PageSheet**: `PageSheetSurface` (the sheet alone), `PageSheetTop`, and `SheetPresenter(stacked, dimmed, cardTop)`, the live presenter under a sheet: shrunk 16 in with its top at the safe-area top under `colors.stackedPresenterDim` (black 11%, sampled from 73a046d0 and 2be9ff97), or dimmed by `sheetDim`. The nav host and `Overlay`/`SheetOverlay` draw sheets with these; `PageSheet(presenter = …)` remains for the old screens.
- **TabBar**: unchanged; MainShell feeds it from the repository (`AppSnapshot.tabBarData`).

## Decisions

- Robolectric SDK 36 (compileSdk is 37; Robolectric 4.17 has no 37 runtime). The Gradle toolchain runs tests on JDK 21, so the test task adds `--add-exports/--add-opens java.base/jdk.internal.access` that SDK 36 needs. Host tests run with `robolectric.graphicsMode=NATIVE` and `pixelCopyRenderMode=hardware` so shadows and blurs render.
- Text renders with Roboto on the Android host and SF Pro on iOS; screenshot widths of text can differ from the source by a few percent. Judge type by size, weight, line box and position, not glyph shapes.
- `material3` was removed from the dependencies. Navigation is `org.jetbrains.androidx.navigation:navigation-compose` 2.10.0-rc01 (the release built against Compose 1.11+/lifecycle 2.11); the Kotlin serialization plugin is applied for type-safe routes in step 6.
- Figma has no smoothing on its corners; the code offers continuous corners because the source is iOS. Components choose.
- The Figma glyph set lacks some glyphs the source screens use (recreate-log: crown, ×2/×3 badges, smile, clapping hands, dollar circle, swap arrows, coins, two-tone Top-up/Bill pay/Transfer, biller logos CFE/water/TV/internet/toll/parking, Beauty/Car rental chips). They are left to the steps that build the components and screens that need them, as new icon files.

## Gotchas

- Kotlin comments nest: writing a foundations name like `` `space/*` `` inside a KDoc opens a second comment and breaks the whole file ("Unclosed comment"). Write `space/…` instead.
- The first test run downloads Robolectric's `android-all` runtime for SDK 36 (a few hundred MB) into `~/.m2`; later runs are offline.
